# Windows 连续缓冲区 I/O 验证

日期：2026-11-06。补丁只调整 `block/file-win32.c` 内一个请求的缓冲区表示，保留原有同步完成、错误处理和 flush 路径。

## 原生代码

Windows x64、MSVC 14.51、Intel Core i7-13700KF。测试直接提取修改前后的实际函数，用适配类型编译后调用真实 Windows 文件 API。

- 34 项功能用例通过，包含内容独立读回、4 GiB 以上偏移、非缓存 I/O、EOF、短写、I/O 错误、内存分配失败和 flush 错误。
- 从本机已有 Git 对象重新回放 mas38 的 95 个补丁，树与发布记录一致。新补丁可以原样 `git am --keep-cr`，应用后同样通过 34 项用例。
- 仓库的 11 组发布补丁全部回放通过。使用原版 `scripts/checks.py patches`，通过 Git URL 映射读取已有本地仓库，并设置 `GIT_ALLOW_PROTOCOL=file`，没有下载 AOSP。
- 元数据与公开隐私规则检查通过。

微基准交替运行修改前后版本，共六轮，比较中位耗时。相同缓存文件范围被重复读写，末尾 flush 不计入计时。

游戏运行的是已核对哈希的 **ModAVD 0.38.1 发布版，没有装入本补丁**。独立新建实例，6 GiB 内存、4 vCPU、1920×1080，NVIDIA GeForce RTX 4060 Ti。`tsc` 时钟和客体 `write through` 状态在采样期间保持不变。安装包来自官网并通过签名校验，版本和哈希见 [games.json](results/games.json)。没有登录账号。

## 强杀后的低速诊断

在发布版明日方舟下载中结束测试 QEMU，未先执行 guest sync，冷启动后游戏可以继续处理资源，但实际网络接收降到约 0.154 MiB/s。同一客体的独立小块写入加真实 fsync 探针仍为 13.62 MiB/s；游戏的两个下载连接接收队列为空，下载线程在等待网络。

客体 DNS 将 `ak.hycdn.cn` 解析到 `43.109.5.15` 一带的节点，宿主解析得到不同节点。对同一个官方资源做两轮交替的 1 MiB HTTP Range 请求，所有响应均为 206、TLS 校验成功、内容 SHA-256 一致。原节点实测约 0.066–0.158 MB/s，另外两个节点约 8.1–11.9 MB/s。

仅把独立测试客体的 `private_dns_mode` 从未设置改成 `off`，再重启一次游戏应用，连接切换到 `60.188.140.124`。之后 60 秒实际游戏网络接收恢复到 10.91 MiB/s，客体没有再次重启。宿主 v2rayN、DNS 和路由未改动。这项临时测试环境调整没有包含在补丁中；恢复原设置的命令是 `settings delete global private_dns_mode`。

证据见 [network-diagnosis.json](results/network-diagnosis.json)。这说明本次极低下载速度来自所选 CDN 节点或到该节点的链路，不证明节点的物理位置，也尚未定位 DNS 与 TUN 的具体上游交互。恢复速度本身不代表已完成整个资源包的解压验证。

同一轮随后继续完成资源处理，进入无下载进度或错误提示的 START 标题页。同步数据并重新启动游戏后，先显示资源完整性检查，随后回到带语音配置提示的标题页，未见重新下载或错误提示。结果见 [arknights-crash-baseline.json](results/arknights-crash-baseline.json)。只做了一轮发布版强杀，未独立扫描所有资源 CRC；这不能替代 #96 active 模式或候选 QEMU 的异常退出验证。

## 尚未验证

本机缺 AEMU、gRPC/protobuf、BoringSSL 等实际源码和开发输入，以及完整构建所需的预编译依赖；现有 SDK 的运行时 DLL 不能替代这些输入。未补齐 AOSP 构建依赖，因此没有编译、启动包含本补丁的完整模拟器。补丁的真实游戏吞吐、连续缓冲区在游戏请求中的比例，以及候选版本的强杀恢复仍待验证。发布版游戏观察不能替代这些检查，也不代表已经完成 #35 的下载速度目标。
