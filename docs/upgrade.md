# 升级

模拟器本体都在 `sdk\emulator\`。升级就是用新包里的这个文件夹整个替换旧的，其余的东西留着不动。

## 哪些要换，哪些不动

| 路径 | 升级时 |
|---|---|
| `sdk\emulator\` | **整个替换**。先删掉旧的再放新的，不要把新文件覆盖到旧文件夹里，否则新版拿掉的文件会留下 |
| `tools\`、`补全组件.bat`、`收集问题信息.bat`、`说明.txt`、`LICENSES\`、`components\` | 用新包里的覆盖 |
| `avd\` | **不动**。实例、游戏和登录状态都在这里 |
| `sdk\platform-tools\`、`sdk\system-images\` | 不动。新版要求的版本变了时，Release 说明里会写，届时再运行「补全组件.bat」 |
| `mas-avd.json`、`logs\` | 不动。这是 AUTO-MAS 和模拟器自己写的 |

## 步骤

1. 在 AUTO-MAS 里关掉所有魔改 AVD 实例，确认任务管理器里没有 `qemu-system-x86_64` 进程。
2. 把新的 Release 包解压到一个临时文件夹。0.32.1 起压缩包里没有外层文件夹，用右键「全部解压缩」会自动建一个同名文件夹。
3. 删掉旧文件夹里的 `sdk\emulator\`，把新包里的 `sdk\emulator\` 放进去。
4. 把新包根目录下的其他文件和文件夹（见上表）覆盖到旧文件夹里。
5. 打开 `sdk\emulator\source.properties`，确认 `Pkg.BuildId` 是新版本号（例如 `mas-35`）。
6. AUTO-MAS 里不用重新添加，照常开机即可。

## 从内测包升级

内测包（例如 `ModAVD-37.2.10-mas25`）自带 adb 和系统镜像，和「补全组件.bat」下载的是同一版本，所以：

- 按上面的步骤替换 `sdk\emulator\`；
- 把新包里的 `tools\`、`补全组件.bat`、`收集问题信息.bat`、`说明.txt`、`LICENSES\` 复制过去（内测包里没有「补全组件.bat」和 `LICENSES\`）；
- 不需要再运行「补全组件.bat」。运行了也没关系，它会显示两样组件都已齐全并跳过。

内测包里的旧实例可以直接用新版开机。

## 版本太旧时

AUTO-MAS 会检查模拟器的版本号（`Pkg.BuildId`），太旧时拒绝开机并提示更新。按上面的步骤换成新版即可。
