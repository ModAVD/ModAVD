# 安装

以 AUTO-MAS 为例。整个过程不需要管理员权限，开启 Windows 功能那一步除外。

## 开始前确认

- Windows 10 / 11，64 位；CPU 是 Intel 或 AMD 的 x86_64。
- 显卡支持 Vulkan（独立显卡或较新的集成显卡）。
- AUTO-MAS：推荐 `v5.7.0` 或更新。v5.7.0-beta.5 起支持 MAA 和全部 MFW 脚本，更早的版本见 Release 说明。
- 找一块空间大的 NTFS 盘：
  - 补全组件时要约 6.5 GB 可用，装完以后组件和模拟器本体共占约 5 GB；
  - 每台实例第一次开机时，所在的盘要有 10 GB 以上可用；
  - 之后实例随游戏数据增长，一个游戏通常几十 GB。删掉游戏或文件以后，实例文件不会变小，但新写入会复用腾出来的空间。

## 1. 下载并解压

当前公开版本为 0.32.1；从 [0.32.1 Release](https://github.com/ModAVD/ModAVD/releases/tag/v0.32.1) 下载 `ModAVD-0.32.1-win-x64.zip`。压缩包里没有外层文件夹，请右键「全部解压缩」，或用 7-Zip「解压到 ModAVD-0.32.1-win-x64\」，得到 `ModAVD-0.32.1-win-x64` 文件夹；不要用「解压到当前文件夹」，否则文件会直接散在压缩包所在的目录里。把它放到一个**只含英文、数字**的路径，可以改名，例如 `D:\ModAVD`。

- 路径里有中文时模拟器起不来，「补全组件.bat」也会直接拒绝。
- 不要放进 `C:\Program Files` 这类要管理员权限的目录。
- 以后所有实例的数据都存在这个文件夹的 `avd\` 里。

解压后的文件夹里有：

| 路径 | 内容 |
|---|---|
| `sdk\emulator\` | 模拟器本体 |
| `components\` | 轻量桌面 µLauncher 的安装包，AUTO-MAS 第一次开机时装进安卓 |
| `tools\` | 两个 bat 调用的 PowerShell 脚本 |
| `补全组件.bat` | 下载 adb 和系统镜像 |
| `收集问题信息.bat` | 出问题时生成问题包 |
| `说明.txt` | 简短说明 |
| `LICENSES\` | 许可证和第三方组件声明 |

## 2. 补全组件

双击「补全组件.bat」。

1. 脚本先从下载镜像取来 Google《Android 软件开发套件许可协议》全文并显示，另存一份到 `downloads\android-sdk-license.txt`。
2. 输入 `y` 回车表示同意；直接回车或输入别的内容就退出，什么也不下载。
3. 同意后下载两样东西，装进 `sdk\`：
   - 平台工具（adb）37.0.1，约 8 MB；
   - 系统镜像 Android 14（API 34）Google APIs x86_64 r14，约 1.5 GB，解压后约 4.2 GB。
4. 镜像按顺序试：googledownloads.cn → 腾讯云镜像 → dl.google.com。一个不通或校验不对就换下一个。
5. 每个文件下完都核对大小和 SHA-1，通过后才解压。中途断了，再运行一次会接着下。
6. 看到「完成，可以在 AUTO-MAS 里添加这个文件夹了。」就好了。

已经装好的组件会跳过，重复运行没有副作用。过程记录在 `logs\fetch-components.log`。

### 补全组件出错时

| 提示 | 怎么办 |
|---|---|
| 路径里有中文或其他非英文字符 | 把整个文件夹挪到纯英文路径下，再运行 |
| 这里没有 sdk\emulator\emulator.exe | Release 压缩包没解压完整，重新解压，在解压出来的文件夹里运行 |
| 磁盘空间不够 | 换一块空间更大的盘 |
| 取不到许可协议全文 / 所有镜像都没下成 | 检查网络后重试；已下的部分会保留 |

下载太慢或总是失败时，可以用浏览器或下载工具手动下载下面两个文件，**文件名不变**放进文件夹里的 `downloads\`，再运行「补全组件.bat」。脚本仍要联网取一次许可协议，然后会校验这两个文件，通过就直接用。装好后脚本会删掉 `downloads\` 里的这两个压缩包。

| 文件 | 地址 | SHA-1 |
|---|---|---|
| `platform-tools_r37.0.1-win.zip` | `https://dl.google.com/android/repository/platform-tools_r37.0.1-win.zip` | `e03e78b1d80b396f1c3358e31251cb31740e1110` |
| `x86_64-34_r14.zip` | `https://dl.google.com/android/repository/sys-img/google_apis/x86_64-34_r14.zip` | `e0f6c9a0691aa27bd597d0deb1bcfdc943ac8ca7` |

把 `dl.google.com/android/repository/` 换成 `googledownloads.cn/android/repository/` 也能下到同样的文件。

## 3. 开启虚拟化

模拟器要用「Windows 虚拟机监控程序平台」：

1. 按 Win+R，输入 `optionalfeatures` 回车，打开「启用或关闭 Windows 功能」。
2. 勾选「Windows 虚拟机监控程序平台」，确定。
3. 重启电脑。

开了还是不行，多半是 BIOS 里没开 CPU 虚拟化。进 BIOS 打开 Intel VT-x 或 AMD SVM，具体位置看主板说明书。

## 4. 在 AUTO-MAS 里添加

1. 打开「模拟器管理」。
2. 还没有模拟器配置的话，点「手动添加模拟器」，把模拟器类型选成「自动识别（推荐）」；已经有这种配置的直接用它。
3. 在这个配置里点「管理模拟器」→「添加魔改 AVD（内测）」，选第 1 步解压的文件夹，点「检查」。
4. 电脑检查全部通过后点「添加」。添加完会自动建好第一台实例。

「检查」里哪一项没通过，就按提示处理；虚拟化没通过见上一节。

## 5. 第一次使用

每台新实例都要先手动开一次机，装游戏、登录账号：

1. 在设备列表里点这台实例的启动按钮。手动启动会显示模拟器窗口。
2. 在窗口里从下往上滑，打开应用列表，用 Chrome 到游戏官网下载安卓安装包并安装。系统提示不允许安装未知应用时，按提示允许 Chrome 安装应用。
3. 打开游戏，登录，下完首次资源，然后在 AUTO-MAS 里关闭实例。

回桌面请用窗口侧边工具栏的 ○ 键；从屏幕底边上滑回不了桌面。

之后由任务拉起时，有没有窗口跟着 AUTO-MAS 的「静默模式」走。具体怎么配合 MAA、M9A 等脚本，以 AUTO-MAS 的说明为准。

## 卸载

先在 AUTO-MAS 的「管理模拟器」里移除这个模拟器，再删掉整个文件夹。崩溃转储（如果有）在 `%TEMP%\AndroidEmulator\emu-crash-37.2.10-mas.db\`，可以一并删掉；同一目录下名字里没有 `-mas` 的是官方模拟器的，不是本项目的。
