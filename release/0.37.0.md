ModAVD 0.37.0，构建号 `mas-37`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见仓库 README 与 `docs/`。

## 更新内容

### 新增

- 《如鸢》国服（com.lingxigames.yuan.cn）能跑了：执行桥的名单加上了它，并且保护转译层自己发起的 vfork / clone，冷启动不再卡死。修复时在测试实例上连续冷启动 20 次都正常，MaaYuan 的日常任务也能跑；这一版的发布前回归没有单独测《如鸢》。（[#20](https://github.com/ModAVD/ModAVD/issues/20)、[#25](https://github.com/ModAVD/ModAVD/pull/25)）
- 用管理器 ModAVD.exe 或命令行 tools\modavd.exe 新建实例时，会在后台不弹窗口地开一次机，把首次设置、执行桥和宿主输入法都装好再正常关机，才算新建完成；之后第一次开机和平常一样快。新建过程中实例显示为「新建中」，带按实际做完的步骤算的百分比，AUTO-MAS 发起的新建在管理器里也看得到；中途失败的，在管理器里点「重试初始化」接着做完。
- 管理器里的「开机」一律带窗口，去掉了「重启」和「显示窗口 / 隐藏窗口」；命令行去掉了 restart，改用先 stop 再 start。实例开着时不再切换有窗口 / 无窗口：命令行要的开机方式和它现在不一样时会报错，不再悄悄接管或重启。
- 命令行 tools\modavd.exe 多了 components（补全组件：下载 adb 和系统镜像）、collect-info（收集问题信息）、report-config（复制配置信息）三个命令，做的事和包里同名的 .bat 一样；还有 update，可以从 GitHub 或 Mirror 酱更新整个 ModAVD 包。

### 变更

- L3 缓存分大小两组的处理器（例如 7950X3D）上，多开时按各组还空着的核数给新实例选组，不再全都挤在大 L3 那组；只开一台时和以前一样。下载时模拟器的忙等循环数按宿主的余量设上限，几台同时下载不会把一组核心占满；逻辑核数不到实例核数两倍的电脑上，只开一台时下载会比以前慢一些。（[#34](https://github.com/ModAVD/ModAVD/issues/34)）
- 包里的管理器 ModAVD.exe 和命令行 tools\modavd.exe 从 0.1.0 升到 0.3.0，各版的改动见 [ModAVDManager 的 Release](https://github.com/ModAVD/ModAVDManager/releases)。
- 模拟器窗口的侧边栏只留下 −、×、◁、○，去掉了没用的电源键和音量键（实例本来就不出声音）。Windows 上 −、× 在系统标题栏上，◁、○ 在画面右侧和画面等高的一列里、贴着底边，提示是「返回」「主页」。设了环境变量 ANDROID_EMU_FULL_TOOLBAR=1 的照旧显示完整的官方工具栏，行为和以前一样。（[#32](https://github.com/ModAVD/ModAVD/issues/32)）

### 修复

- 点模拟器窗口的 × 不再等于直接断电：窗口马上消失，安卓在后台正常关机；15 秒内没关完，先把数据写回磁盘再退出。以前点 × 时游戏最后几秒写的文件可能丢失或变成 0 字节。Alt+F4 和任务栏的「关闭窗口」走同一条路。（[#32](https://github.com/ModAVD/ModAVD/issues/32)）
- 《阴阳师》等只有 arm64 版本的游戏冷启动时偶尔卡住：执行桥现在也保护转译层自己发起的 vfork / clone，子进程不会再卡在转译层的内部锁上。装过执行桥的实例，升级后第一次用管理器或命令行开机时会自动换上新的执行桥。（[#25](https://github.com/ModAVD/ModAVD/pull/25)）
- 宿主输入法一次提交的长文字，要么整段送进安卓，要么整段不送，不会再只送进前半段。（[#17](https://github.com/ModAVD/ModAVD/pull/17)）
- 老实例第一次开机把数据盘从 ext4 转成 qcow2 时，转换失败会保留原来的镜像、照常开机，不会再用转了一半的文件换掉原盘。（[#11](https://github.com/ModAVD/ModAVD/pull/11)）
- 用管理器或命令行开机时，等 /sdcard 真能写进文件再返回；以前刚开完机马上往 /sdcard 写文件可能失败。
- 图形：同步读回画面失败时，不再把旧画面当成新的一帧交给截图和录屏。（[#12](https://github.com/ModAVD/ModAVD/pull/12)）
- 图形：按需增长的暂存缓冲按缓冲本身的大小判断够不够用；以前驱动多分配了一点内存时，略超出缓冲大小的请求也会被当成够用。（[#10](https://github.com/ModAVD/ModAVD/pull/10)）
- 磁盘读写在非缓存模式下保持缓冲区对齐，读出错时如实报错，不再当成读到了文件末尾。默认配置不走这条路。（[#9](https://github.com/ModAVD/ModAVD/pull/9)）

### 说明

- 点 × 以后，模拟器进程还会在后台运行 5–20 秒（安卓在关机），任务管理器里还能看到它，请不要结束它。这段时间里用管理器或命令行重开同一台，会等它关完再开机。
- Windows 标题栏上会多出一个灰色、点不了的最大化按钮，× 的悬停提示是系统的「关闭」；以后改成自己画标题栏（[#58](https://github.com/ModAVD/ModAVD/issues/58)）。没有窗口的实例（例如 AUTO-MAS 后台运行的）不受这次改动影响。

## 怎么更新

- 先关掉所有实例（在 AUTO-MAS 或管理器里关机）再更新；关掉后稍等半分钟，模拟器的附属进程退出要十几秒，覆盖时提示文件被占用就再等一会儿重试。手动更新时用新包整个覆盖解压，`avd` 文件夹不会被动到。不用重新下载组件，也不用在 AUTO-MAS 里重新添加。
- 装过执行桥的实例，升级后第一次用管理器或命令行开机时，会自动换上这一版的执行桥，中间多冷启动一次。只用 AUTO-MAS 开机的实例不会自动换，请用管理器开一次机，或在包根打开 PowerShell 运行一次 `tools\modavd.exe bridge <编号> install`。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击「补全组件.bat」下载 adb 和系统镜像，再双击 `ModAVD.exe` 新建实例；要接入 AUTO-MAS 的，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 0.36.0 相同。这一版对 AUTO-MAS 没有新要求。

## 已知问题

- 删除游戏或文件后虚拟磁盘不缩小；后续写入会复用空间。（[#2](https://github.com/ModAVD/ModAVD/issues/2)）
- FAT32 / exFAT 上的首次建盘空间检查尚未实测，建议使用 NTFS。（[#3](https://github.com/ModAVD/ModAVD/issues/3)）
- 《阴阳师》冷启动偶尔停在「正在获取音频列表...」，关掉重开即可。（[#36](https://github.com/ModAVD/ModAVD/issues/36)）
- 多开时 netsimd 偶尔卡住，之后所有实例都开不了机；在任务管理器里结束 netsimd 进程再开机就好。（[#65](https://github.com/ModAVD/ModAVD/issues/65)）
- Windows 注销、重启或关机时，开着的实例还是直接断电，不会先让安卓关机，和以前一样。关电脑前请先在 AUTO-MAS 或管理器里关掉实例。（[#60](https://github.com/ModAVD/ModAVD/issues/60)）

## English

ModAVD 0.37.0, build `mas-37`, built on Google AOSP Android Emulator 37.2.10. Installation, upgrades and feedback: see https://modavd.github.io/.

### New

- *Ruyuan* (China server, `com.lingxigames.yuan.cn`) now runs: it is on the execution bridge's list, and the bridge guards the vfork / clone calls the translator makes itself, so its cold start no longer hangs. While fixing it, 20 cold starts in a row on a test instance all went through and MaaYuan's daily tasks ran; this version's pre-release regression did not test *Ruyuan* separately. ([#20](https://github.com/ModAVD/ModAVD/issues/20), [#25](https://github.com/ModAVD/ModAVD/pull/25))
- When you create an instance with the manager ModAVD.exe or the command line tools\modavd.exe, it now boots once in the background without a window, sets up the first-boot settings, the execution bridge and the host input method, and shuts down properly; only then is the instance created. Its first start afterwards is as fast as any other. While it is being created the instance shows as "creating" with a percentage based on the steps actually done, and the manager also shows the progress of a creation that AUTO-MAS started; if creating fails halfway, "重试初始化" (retry setup) in the manager finishes it.
- "Start" in the manager now always opens a window, and "Restart" and "Show window / Hide window" are gone. The command line drops restart; use stop and then start. A running instance no longer switches between window and no window: if the command line asks for the other mode, it reports an error instead of quietly taking over or restarting the instance.
- The command line tools\modavd.exe has three new commands that do what the .bat files of the same purpose in the package do: components (download adb and the system image), collect-info (collect diagnostic information) and report-config (copy the configuration). It also has update, which updates the whole ModAVD package from GitHub or MirrorChyan.

### Changes

- On processors whose L3 cache comes in a large and a small group (such as the 7950X3D), each new instance now goes to the group with the larger share of free cores instead of all instances being crowded onto the large-L3 group; a single instance is placed as before. The emulator's busy-wait loops during downloads are capped by the host's spare cores, so a few instances downloading at once no longer saturate one group of cores; on computers with fewer than twice as many logical cores as the instance has, even a single instance downloads a little slower than before. ([#34](https://github.com/ModAVD/ModAVD/issues/34))
- The manager ModAVD.exe and the command line tools\modavd.exe in the package go from 0.1.0 to 0.3.0; see the [ModAVDManager releases](https://github.com/ModAVD/ModAVDManager/releases) for what changed in each version.
- The side toolbar of the emulator window now has only −, ×, ◁ and ○. The power and volume keys are gone (instances have no sound anyway). On Windows, − and × are on the system title bar, and ◁ and ○ sit at the bottom of a column on the right of the screen that is as tall as the screen; their tooltips are "Back" and "Home" in Chinese. With the environment variable ANDROID_EMU_FULL_TOOLBAR=1 you still get the full upstream toolbar, which behaves as before. ([#32](https://github.com/ModAVD/ModAVD/issues/32))

### Fixes

- Clicking × on the emulator window no longer pulls the plug: the window disappears at once and Android shuts down properly in the background; if it has not finished within 15 seconds, the data is written back to disk before the emulator exits. Before, files a game wrote in its last seconds could be lost or end up empty. Alt+F4 and "Close window" on the taskbar take the same path. ([#32](https://github.com/ModAVD/ModAVD/issues/32))
- Games that ship only arm64 code, such as Onmyoji, no longer hang now and then during a cold start: the execution bridge now also guards the vfork / clone calls the translator makes itself, so a child process no longer gets stuck on the translator's internal locks. Instances that have the execution bridge get the new bridge automatically the first time they are started from the manager or the command line after the update. ([#25](https://github.com/ModAVD/ModAVD/pull/25))
- Long text committed with the host input method now reaches Android whole or not at all; it is no longer cut off after the first part. ([#17](https://github.com/ModAVD/ModAVD/pull/17))
- When an old instance converts its data disk from ext4 to qcow2 on first boot and the conversion fails, the original image is kept and the instance boots as usual; a half-converted file can no longer replace the original disk. ([#11](https://github.com/ModAVD/ModAVD/pull/11))
- A start from the manager or the command line now returns only once /sdcard can really be written to. Before, writing a file to /sdcard right after the boot could fail.
- Graphics: when a synchronous readback of the screen fails, the old picture is no longer handed to screenshots and recordings as a new frame. ([#12](https://github.com/ModAVD/ModAVD/pull/12))
- Graphics: the staging buffer that grows on demand now checks requests against the size of the buffer itself. Before, when the driver allocated a little more memory than asked for, a request slightly larger than the buffer could be taken as fitting. ([#10](https://github.com/ModAVD/ModAVD/pull/10))
- Disk I/O in uncached mode keeps its buffers aligned, and read errors are reported as errors instead of being taken as end of file. The default configuration does not use this path. ([#9](https://github.com/ModAVD/ModAVD/pull/9))

### Notes

- After you click ×, the emulator process keeps running in the background for 5–20 seconds while Android shuts down, and you can still see it in Task Manager. Please do not end it. If you start the same instance again from the manager or the command line during this time, it waits for the shutdown to finish and then starts it.
- The Windows title bar shows a greyed-out maximize button that cannot be clicked, and the tooltip of × is the system's "Close". A title bar of our own is planned ([#58](https://github.com/ModAVD/ModAVD/issues/58)). Instances without a window (for example ones AUTO-MAS runs in the background) are not affected by these changes.

### How to update

- Shut down all instances first (in AUTO-MAS or in the manager), then wait about half a minute: the emulator's helper processes take a dozen seconds or so to exit. If extracting reports a file in use, wait a little and try again. To update by hand, extract the whole new package over the old one; the `avd` folder is left alone. There is no need to download the components again or to add ModAVD to AUTO-MAS again.
- Instances that have the execution bridge get this version's bridge automatically the first time they are started from the manager or the command line after the update, with one extra cold boot. Instances that are only ever started by AUTO-MAS are not updated automatically: start them once from the manager, or open PowerShell in the package root and run `tools\modavd.exe bridge <number> install` once.
- First install: the main package has no top-level folder, so use "Extract All…" or 7-Zip "Extract to <package name>\". Then double-click 补全组件.bat to download adb and the system image, and double-click `ModAVD.exe` to create an instance. To use it with AUTO-MAS, add it there as well; see 说明.txt.

### AUTO-MAS version

- `v5.7.0` or later is recommended, as for 0.36.0. This version has no new requirements for AUTO-MAS.

### Known issues

- The virtual disk does not shrink after games or files are deleted; later writes reuse the space. ([#2](https://github.com/ModAVD/ModAVD/issues/2))
- The free-space check for creating the first disk on FAT32 / exFAT has not been tested; NTFS is recommended. ([#3](https://github.com/ModAVD/ModAVD/issues/3))
- Onmyoji occasionally stops at "正在获取音频列表..." (fetching the audio list) during a cold start; close it and start it again. ([#36](https://github.com/ModAVD/ModAVD/issues/36))
- With several instances, netsimd occasionally hangs, and after that no instance can start; end the netsimd process in Task Manager and start again. ([#65](https://github.com/ModAVD/ModAVD/issues/65))
- When Windows logs off, restarts or shuts down, running instances are still cut off without letting Android shut down first, as before. Shut the instances down in AUTO-MAS or the manager before turning off the computer. ([#60](https://github.com/ModAVD/ModAVD/issues/60))
