ModAVD 0.39.1，构建号 `mas-39`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见仓库 README 与 `docs/`。

## 更新内容

### 新增

- 管理器「设置」里的「更新」能用了：下载核对后正常关掉实例，交给命令行换包，换好自动重新打开管理器。更新到这一版本身还是照原来的办法。

### 变更

- 只重新打包：模拟器还是 mas-39；包里的管理器和命令行升到 0.7.0，详见 [ModAVDManager 的 Release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.7.0)。
- Windows 上由管理器或命令行开机时多带两项设置，小块同步写盘快约 1.5 倍：明日方舟下资源约 7.5 → 11.5 MiB/s，下载时不再把每个核占满。（[#35](https://github.com/ModAVD/ModAVD/issues/35)）
- 开机前不再按空闲内存拦着；模拟器真分不到内存时报内存不足。问题包多收管理器日志、adb 日志和 Windows 保留的端口。

### 修复

- Windows 10.0.26300 上新建、开机要等满 300 秒才失败：管理器看不到已经在运行的私有 adb server。安卓开好而 adb 连不上时，现在 60 秒内就报出原因；补全组件挪目录被安全软件占着时先重试，再改用复制。（[#172](https://github.com/ModAVD/ModAVD/issues/172)）

## 怎么更新

- 这一版只重新打包：模拟器还是 mas-39，没有重编；包里的管理器和命令行升到 0.7.0（改动见 [它的 Release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.7.0)）；截图库、执行桥、宿主输入法都和 0.39.0 一样。
- 在 Windows 10.0.26300 上新建、开机要等满 300 秒才失败的，更新到这一版就好了。（[#172](https://github.com/ModAVD/ModAVD/issues/172)）
- 管理器「设置」里的「更新」从这一版起能用了；更新到这一版本身，还是照下面原来的办法。
- 先关掉所有实例（在 AUTO-MAS 或管理器里关机）再更新；关掉后稍等半分钟再覆盖。手动更新时用新包整个覆盖解压，`avd` 文件夹不会被动到。不用在 AUTO-MAS 里重新添加。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击 `ModAVD.exe`，点上方提示里的「补全组件」下载 adb 和系统镜像，再新建实例；要接入 AUTO-MAS 的，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 0.39.0 相同。这一版对 AUTO-MAS 没有新要求：管理器 0.7.0 的接口版本（`protocol`）还是 2。新加的错误码 `insufficient_memory`（退出码 10）在模拟器分不到内存时报，开机前也不再因为内存报 `precheck_failed`；不认识退出码 10 的按一般失败处理就行。
- AUTO-MAS 5.8.0 测试版在组件不全时还会提示双击「补全组件.bat」，0.38.2 起包里没有这个文件：请在管理器里点「补全组件」，或运行 `tools\modavd.exe components fetch`，再回 AUTO-MAS 点「检查」。

## 已知问题

- 删除游戏或文件后虚拟磁盘不会自动缩小，模拟器的 trim 还不会真正回收空间；要省空间，请在关机后用管理器的「整理磁盘」或命令行 `modavd disk <编号> compact`。（[#2](https://github.com/ModAVD/ModAVD/issues/2)）
- 《阴阳师》冷启动偶尔停在「正在获取音频列表...」，关掉重开即可。（[#36](https://github.com/ModAVD/ModAVD/issues/36)）
- AUTO-MAS 自己起的模拟器（不经过管理器或命令行），多开时 netsimd 还可能卡住，之后所有实例都开不了机；在任务管理器里结束 netsimd 进程再开机就好。用管理器或命令行开机的实例已经不用 netsimd 了。（[#65](https://github.com/ModAVD/ModAVD/issues/65)）
- Windows 注销、重启或关机时，没有窗口的实例（命令行或 AUTO-MAS 在后台开的）还是直接断电，不会先让安卓关机。关电脑前请先在 AUTO-MAS 或管理器里关掉实例。（[#64](https://github.com/ModAVD/ModAVD/issues/64)）
- 《明日方舟》偶尔在启动时报资源管理器初始化失败，随后把约 12.8 GB 的资源整包重新下载一遍；遇到过两次，排查都没有发现模拟器丢数据，更像游戏自己把资源索引作废了，等它下完即可。（[#89](https://github.com/ModAVD/ModAVD/issues/89)）

## English

ModAVD 0.39.1, build `mas-39`, built on Google AOSP Android Emulator 37.2.10. Installation, upgrades and feedback: see https://modavd.github.io/.

### New

- "更新" (update) in the manager's "设置" (settings) now works: once the new version is downloaded and checked, the manager stops the instances normally, hands over to the command line to swap the package, and opens again when that is done. Updating to this version itself still works the old way.

### Changes

- Repackaged only: the emulator is still mas-39; the manager and the command line in the package go to 0.7.0, see the [ModAVDManager release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.7.0).
- On Windows, boots by the manager or the command line add two settings that make small synchronous disk writes about 1.5 times as fast: Arknights resource downloads go from about 7.5 to about 11.5 MiB/s, and downloads no longer max out those cores. ([#35](https://github.com/ModAVD/ModAVD/issues/35))
- Free memory no longer blocks a boot; when the emulator really cannot get the instance's memory, the error says so. The problem package also collects the manager's logs, the adb logs and the TCP ports Windows reserves.

### Fixes

- On Windows 10.0.26300, creating or starting an instance failed only after the full 300 seconds: the manager could not see the private adb server that was already running. When Android has booted but adb cannot reach it, the reason is now reported within 60 seconds; when fetching components, moving a folder that security software holds open is retried and then done by copying. ([#172](https://github.com/ModAVD/ModAVD/issues/172))

### How to update

- This version is repackaged only: the emulator is still mas-39, not rebuilt; the manager and the command line in the package go to 0.7.0 (see [its release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.7.0)); the capture library, the execution bridge and the host input method are the same as in 0.39.0.
- If creating or starting an instance on Windows 10.0.26300 failed only after waiting the full 300 seconds, updating to this version fixes it. ([#172](https://github.com/ModAVD/ModAVD/issues/172))
- "更新" (update) in the manager's "设置" (settings) works from this version on; to update to this version itself, use the old way below.
- Shut down all instances first (in AUTO-MAS or in the manager), then wait about half a minute before extracting. To update by hand, extract the whole new package over the old one; the `avd` folder is left alone. There is no need to add ModAVD to AUTO-MAS again.
- First install: the main package has no top-level folder, so use "Extract All…" or 7-Zip "Extract to <package name>\". Then double-click `ModAVD.exe`, click "补全组件" in the notice at the top to download adb and the system image, and create an instance. To use it with AUTO-MAS, add it there as well; see `说明.txt`.

### AUTO-MAS version

- `v5.7.0` or later is recommended, as for 0.39.0. This version has no new requirements for AUTO-MAS: the interface version (`protocol`) of manager 0.7.0 is still 2. The new error code `insufficient_memory` (exit code 10) is returned when the emulator cannot get its memory, and memory no longer causes `precheck_failed` before a boot; a caller that does not know exit code 10 can treat it as a general failure.
- When components are missing, the AUTO-MAS 5.8.0 betas still say to double-click `补全组件.bat`, which is not in the package from 0.38.2 on: click "补全组件" in the manager or run `tools\modavd.exe components fetch`, then go back to AUTO-MAS and click "检查" (check).

### Known issues

- The virtual disk does not shrink by itself after games or files are deleted, and the emulator's trim does not actually reclaim space yet; to save space, after shutdown use "compact disk" in the manager or `modavd disk <number> compact`. ([#2](https://github.com/ModAVD/ModAVD/issues/2))
- Onmyoji occasionally stops at "正在获取音频列表..." (fetching the audio list) during a cold start; close it and start it again. ([#36](https://github.com/ModAVD/ModAVD/issues/36))
- Emulators that AUTO-MAS starts itself (not through the manager or the command line) can still hit a hung netsimd with several instances, after which no instance can start; end the netsimd process in Task Manager and start again. Instances started from the manager or the command line no longer use netsimd. ([#65](https://github.com/ModAVD/ModAVD/issues/65))
- When Windows logs off, restarts or shuts down, instances without a window (started in the background from the command line or by AUTO-MAS) are still cut off without letting Android shut down first. Shut the instances down in AUTO-MAS or the manager before turning off the computer. ([#64](https://github.com/ModAVD/ModAVD/issues/64))
- Arknights occasionally reports a resource manager initialization failure at startup and then downloads the whole ~12.8 GB of resources again. It has been seen twice; neither investigation found the emulator losing data, and it looks more like the game invalidating its own resource index. Let the download finish. ([#89](https://github.com/ModAVD/ModAVD/issues/89))

### Pre-release regression

This version is repackaged only and the emulator is the same as in 0.39.0, so only what changed was tested, once each. The regression used this version's candidate package: the manager and the command line were built from the head of the ModAVDManager 0.7.0 release PR and are byte for byte the released v0.7.0 (the SHA-256 of the zip and of both exes match); the capture library, the host input method and the execution bridge are the same as in 0.39.0. Upgrading from 0.39.0 with 0.39.0's own `update install` and by extracting over it, booting and shutting down with the two new disk settings in place, creating instances with the execution bridge and with a new data disk, the host input method, fetching components, Arknights and World of Airports for three minutes each, copying the configuration, collecting problem info, the package contents and the privacy scan all passed. The Windows 10.0.26300 problem ([#172](https://github.com/ModAVD/ModAVD/issues/172)) cannot be reproduced on the test machine: the change to how the manager tells whether the private adb server is there has unit tests and a mutation check, and during development the manager booted normally after re-registering an instance whose private adb server had been killed again and again, so that the emulator's one registration at the end of the boot was lost. The update button in the manager, running out of memory and a component folder held open by security software could not be exercised here and have unit tests only. The results table is in the Chinese section above.
