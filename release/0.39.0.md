ModAVD 0.39.0，构建号 `mas-39`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见仓库 README 与 `docs/`。

## 更新内容

### 新增

- World of Airports 3.7.3 这类用新版 Unity（6000.3）做的、只有 arm64 版本的游戏能跑了：管理器和命令行开机时多挂一个 ARM 转译层补丁，客体 Vulkan 驱动补丁多修一处；按实例的实验开关「报告 GLES 3.2」让 Play 商店能装上。（[#131](https://github.com/ModAVD/ModAVD/issues/131)）
- 包里多了截图库 extras\modavd_extras.dll（[ModAVDExtras](https://github.com/ModAVD/ModAVDExtras) v0.1.1）：自动化工具可以从根目录的 extras\ 载入它，直接读模拟器共享的画面，不经 adb。MAA、AUTO-MAS 还没有接入，现在的截图方式照旧能用。

### 变更

- 模拟器重新编译（mas-38 到 mas-39）：Windows 上一次读写的多段缓冲首尾相接时，直接一次读写，不再先复制或逐段调用（[#126](https://github.com/ModAVD/ModAVD/pull/126)）；gfxstream、Crashpad 没变。
- 包里的管理器和命令行升到 0.6.0，详见 [ModAVDManager 的 Release](https://github.com/ModAVD/ModAVDManager/releases)；开机进度里的「客体 Vulkan 修复」改叫「客体库补丁」。

### 修复

- 不用永久 cache 时（disk.cachePartition=no 或 -no-cache），正常关机后临时目录里不再留下 cache 的 .qcow2 写层。（[#123](https://github.com/ModAVD/ModAVD/pull/123)）
- 实例的 config.ini 读不到或没写 abi.type 时，客体 Vulkan 驱动补丁不再被跳过。（[#130](https://github.com/ModAVD/ModAVD/issues/130)）

### 说明

- 「报告 GLES 3.2」只改报给应用的版本，实际渲染还是 GLES 3.1：走 Vulkan 的游戏能用，真要 GLES 3.2 渲染的应用装得上、打不开。默认关，有问题先关掉。
- 这次的磁盘读写改动没有让明日方舟下资源变快（回归里约 8.9 MB/s，和以前差不多），下载慢的问题还在查。（[#35](https://github.com/ModAVD/ModAVD/issues/35)）

## 怎么更新

- 这一版重新编译了模拟器（mas-39）；包里的管理器和命令行升到 0.6.0（改动见 [它的 Release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.6.0)），还多了截图库 `extras\modavd_extras.dll`（[ModAVDExtras v0.1.1](https://github.com/ModAVD/ModAVDExtras/releases/tag/v0.1.1)）；执行桥、宿主输入法都和 0.38.2 一样。
- 截图库是给 MAA 这类自动化工具用的，接口和用法见 [ModAVDExtras](https://github.com/ModAVD/ModAVDExtras)。MAA、AUTO-MAS 还没有接入它，什么都不用改：AUTO-MAS 现在的截图方式照旧能用。
- 要玩 World of Airports 这类游戏的：实例要有执行桥，装着 Google Play 商店并登录拥有这个游戏的账号（游戏启动时会做 Play 许可检查）。在实例的「更多操作」里开启「报告 GLES 3.2（实验）」（会冷启动一次，要几分钟），再到实例里 设置 → 应用 → Google Play 商店 → 存储 清除数据（账号不会退出），商店就能装了。两个客体库补丁是管理器或命令行开机时挂上的。（[#131](https://github.com/ModAVD/ModAVD/issues/131)）
- 先关掉所有实例（在 AUTO-MAS 或管理器里关机）再更新；关掉后稍等半分钟再覆盖。手动更新时用新包整个覆盖解压，`avd` 文件夹不会被动到。不用在 AUTO-MAS 里重新添加。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击 `ModAVD.exe`，点上方提示里的「补全组件」下载 adb 和系统镜像，再新建实例；要接入 AUTO-MAS 的，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 0.38.2 相同。这一版对 AUTO-MAS 没有新要求：管理器 0.6.0 只加了命令和字段，接口版本（`protocol`）还是 2。
- AUTO-MAS 5.8.0 测试版在组件不全时还会提示双击「补全组件.bat」，0.38.2 起包里没有这个文件：请在管理器里点「补全组件」，或运行 `tools\modavd.exe components fetch`，再回 AUTO-MAS 点「检查」。

## 已知问题

- 删除游戏或文件后虚拟磁盘不会自动缩小，模拟器的 trim 还不会真正回收空间；要省空间，请在关机后用管理器的「整理磁盘」或命令行 `modavd disk <编号> compact`。（[#2](https://github.com/ModAVD/ModAVD/issues/2)）
- 《阴阳师》冷启动偶尔停在「正在获取音频列表...」，关掉重开即可。（[#36](https://github.com/ModAVD/ModAVD/issues/36)）
- AUTO-MAS 自己起的模拟器（不经过管理器或命令行），多开时 netsimd 还可能卡住，之后所有实例都开不了机；在任务管理器里结束 netsimd 进程再开机就好。用管理器或命令行开机的实例已经不用 netsimd 了。（[#65](https://github.com/ModAVD/ModAVD/issues/65)）
- Windows 注销、重启或关机时，没有窗口的实例（命令行或 AUTO-MAS 在后台开的）还是直接断电，不会先让安卓关机。关电脑前请先在 AUTO-MAS 或管理器里关掉实例。（[#64](https://github.com/ModAVD/ModAVD/issues/64)）
- 《明日方舟》偶尔在启动时报资源管理器初始化失败，随后把约 12.8 GB 的资源整包重新下载一遍；遇到过两次，排查都没有发现模拟器丢数据，更像游戏自己把资源索引作废了，等它下完即可。（[#89](https://github.com/ModAVD/ModAVD/issues/89)）

## English

ModAVD 0.39.0, build `mas-39`, built on Google AOSP Android Emulator 37.2.10. Installation, upgrades and feedback: see https://modavd.github.io/.

### New

- Arm64-only games built with the new Unity (6000.3), such as World of Airports 3.7.3, now run: the manager and the command line mount one more patch, for the ARM translation layer, at boot, and the guest Vulkan driver patch fixes one more bug; the per-instance experimental switch "报告 GLES 3.2" (report GLES 3.2) lets the Play Store install them. ([#131](https://github.com/ModAVD/ModAVD/issues/131))
- The package now carries the capture library `extras\modavd_extras.dll` ([ModAVDExtras](https://github.com/ModAVD/ModAVDExtras) v0.1.1): automation tools can load it from the root's `extras\` and read the frames the emulator shares, without adb. MAA and AUTO-MAS do not use it yet; the way they capture today keeps working.

### Changes

- The emulator was rebuilt (mas-38 to mas-39): on Windows, a read or write whose buffers follow one another in memory is now done with one call, without copying them first or making one call per buffer ([#126](https://github.com/ModAVD/ModAVD/pull/126)); gfxstream and Crashpad are unchanged.
- The manager and the command line in the package go from 0.5.0 to 0.6.0; see the [ModAVDManager releases](https://github.com/ModAVD/ModAVDManager/releases) for what changed in them. In the boot progress, "客体 Vulkan 修复" (guest Vulkan fix) is now called "客体库补丁" (guest library patches).

### Fixes

- Without a persistent cache (`disk.cachePartition=no` or `-no-cache`), the cache's `.qcow2` overlay is no longer left in the temporary folder after a normal shutdown. ([#123](https://github.com/ModAVD/ModAVD/pull/123))
- The guest Vulkan driver patch is no longer skipped when the instance's `config.ini` cannot be read or has no `abi.type`. ([#130](https://github.com/ModAVD/ModAVD/issues/130))

### Notes

- "Report GLES 3.2" only changes the version reported to apps; rendering is still GLES 3.1. Games that use Vulkan work, while an app that really renders with GLES 3.2 installs but does not start. It is off by default; if something goes wrong, turn it off first.
- The disk I/O change in this version did not make Arknights resource downloads faster (about 8.9 MB/s in the regression, much as before); the slow download is still being looked into. ([#35](https://github.com/ModAVD/ModAVD/issues/35))

### How to update

- This version rebuilds the emulator (mas-39); the manager and the command line go to 0.6.0 (see [its release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.6.0)), and the package adds the capture library `extras\modavd_extras.dll` ([ModAVDExtras v0.1.1](https://github.com/ModAVD/ModAVDExtras/releases/tag/v0.1.1)); the execution bridge and the host input method are the same as in 0.38.2.
- The capture library is for automation tools such as MAA; its interface and usage are in [ModAVDExtras](https://github.com/ModAVD/ModAVDExtras). MAA and AUTO-MAS do not use it yet, so there is nothing to change: the way AUTO-MAS captures today keeps working.
- To play games such as World of Airports: the instance needs the execution bridge, and the Google Play Store signed in with an account that owns the game (the game runs a Play license check at launch). Turn on "报告 GLES 3.2（实验）" (report GLES 3.2, experimental) in the instance's "更多操作" (more actions) menu (it boots the instance cold once, which takes a few minutes), then in the instance go to Settings → Apps → Google Play Store → Storage and clear its data (the account stays signed in); the store can then install the game. The two guest library patches are mounted when the manager or the command line boots the instance. ([#131](https://github.com/ModAVD/ModAVD/issues/131))
- Shut down all instances first (in AUTO-MAS or in the manager), then wait about half a minute before extracting. To update by hand, extract the whole new package over the old one; the `avd` folder is left alone. There is no need to add ModAVD to AUTO-MAS again.
- First install: the main package has no top-level folder, so use "Extract All…" or 7-Zip "Extract to <package name>\". Then double-click `ModAVD.exe`, click "补全组件" in the notice at the top to download adb and the system image, and create an instance. To use it with AUTO-MAS, add it there as well; see `说明.txt`.

### AUTO-MAS version

- `v5.7.0` or later is recommended, as for 0.38.2. This version has no new requirements for AUTO-MAS: manager 0.6.0 only adds commands and fields, and the interface version (`protocol`) is still 2.
- When components are missing, the AUTO-MAS 5.8.0 betas still say to double-click `补全组件.bat`, which is not in the package from 0.38.2 on: click "补全组件" in the manager or run `tools\modavd.exe components fetch`, then go back to AUTO-MAS and click "检查" (check).

### Known issues

- The virtual disk does not shrink by itself after games or files are deleted, and the emulator's trim does not actually reclaim space yet; to save space, after shutdown use "compact disk" in the manager or `modavd disk <number> compact`. ([#2](https://github.com/ModAVD/ModAVD/issues/2))
- Onmyoji occasionally stops at "正在获取音频列表..." (fetching the audio list) during a cold start; close it and start it again. ([#36](https://github.com/ModAVD/ModAVD/issues/36))
- Emulators that AUTO-MAS starts itself (not through the manager or the command line) can still hit a hung netsimd with several instances, after which no instance can start; end the netsimd process in Task Manager and start again. Instances started from the manager or the command line no longer use netsimd. ([#65](https://github.com/ModAVD/ModAVD/issues/65))
- When Windows logs off, restarts or shuts down, instances without a window (started in the background from the command line or by AUTO-MAS) are still cut off without letting Android shut down first. Shut the instances down in AUTO-MAS or the manager before turning off the computer. ([#64](https://github.com/ModAVD/ModAVD/issues/64))
- Arknights occasionally reports a resource manager initialization failure at startup and then downloads the whole ~12.8 GB of resources again. It has been seen twice; neither investigation found the emulator losing data, and it looks more like the game invalidating its own resource index. Let the download finish. ([#89](https://github.com/ModAVD/ModAVD/issues/89))
