ModAVD 0.36.0，构建号 `mas-36`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见仓库 README 与 `docs/`。

## 更新内容

### 新增

- 只有 arm64 版本、带加固的游戏可以跑起来了（先验的是《阴阳师》）：包里多了一个执行桥，装进实例以后，游戏加固库装在系统库里的钩子能正确执行并返回。不修改游戏的任何文件，也不修改安卓自带的转译层。
- 执行桥不用自己装：用管理器 ModAVD.exe 或命令行 tools\modavd.exe 开机时，实例会自动装上（新建的和已有的都一样，第一次要多关机再开机一两次，约 1–2 分钟）。只用 AUTO-MAS 开机的实例暂时不会自动装，用管理器开一次机就装上。装过桥的实例照常用 AUTO-MAS 开机，桥一直在。
- 执行桥只对《阴阳师》的各渠道包生效：官服、雷电 / MuMu 下载的官服、bilibili、华为、OPPO、vivo、应用宝。别的应用一启动就回到原来的转译层，和没装桥一样。
- 包根多了实例管理器 ModAVD.exe（双击打开，新建、设置、开关实例，看画面、装 APK、看日志）和命令行 tools\modavd.exe（也能当 MCP 服务器给 AI 助手用）。和 AUTO-MAS 管的是同一批实例。
- 数据盘可以改大，游戏数据不动：用命令行 tools\modavd.exe 的 set 命令（modavd help set 看用法），下次开机生效，只能改大。
- 用管理器 ModAVD.exe 或命令行 tools\modavd.exe 开机的实例，会自动装上宿主输入法并设成默认输入法：在模拟器窗口里点到输入框，就能直接用 Windows 输入法打中文等文字。默认输入法只在第一次装好时改一次，而且只替换镜像自带的键盘，之后换成别的输入法不会被改回。用 AUTO-MAS 开机的实例暂时不会自动装。
- 装了执行桥的实例，图形命令改走共享内存（asg）传给电脑显卡，不再经内核管道逐条写入：《阴阳师》庭院从 44–48 fps 提到 60 fps，战斗约 57 fps。装桥后下次冷启动生效，卸桥时改回；别的实例不变。

### 变更

- 以后新建的实例少占约 0.7 GB 磁盘：建数据盘时 inode 最多 1,048,576 个，64 GB 分区的 inode 表从 1024 MiB 降到 256 MiB。已有实例不变。（[#6](https://github.com/ModAVD/ModAVD/issues/6)）
- ModAVD 自己的程序和随包脚本（管理器、命令行、arm64 执行桥、宿主输入法、补全组件和问题收集等脚本）都按 AGPL-3.0-or-later 发布（随包脚本以前是 Apache-2.0），源码在 [ModAVDManager](https://github.com/ModAVD/ModAVDManager)、[ModAVDHostIME](https://github.com/ModAVD/ModAVDHostIME) 两个仓库和 ModAVD 仓库的 [package](https://github.com/ModAVD/ModAVD/tree/main/package)、[bridge](https://github.com/ModAVD/ModAVD/tree/main/bridge) 目录，这一版的源码也都在 Release 的附件里。

### 修复

- 以后按 16 GB 建的数据盘可以完整地改大。之前的版本按 16 GB 及以下建的盘结构有缺陷，只能改到约 30 GB。
- 修好模拟器偶尔整个退出的问题：adb 断开又重连的那一下（例如实例重启后），模拟器注销网络监听时可能读到空指针而崩溃。这是官方模拟器代码里的问题，以前的版本都有，发版前回归里遇到一次。

### 说明

- 退回更早的版本之前，请先在装过桥的实例上把桥卸掉，见「怎么更新」。不先卸可能让那台实例跑不了任何只有 arm64 版本的应用，而且界面上看不出来。
- arm64 执行桥只在《阴阳师》官服上实测过；其他渠道包是同一个游戏、同一套加固，一并放进了名单。其它只有 arm64 版本的游戏机理相同，要逐个验证后才会加进清单。
- 0.36.0 之前按 16 GB 及以下建的实例，数据盘只能改到约 30 GB，更大要新建实例再搬游戏。管理器的设置里还没有数据盘大小这一项，要用命令行改。
- 装了宿主输入法的实例带窗口时，应用自己收起输入框以后（例如聊天框点「发送」后输入框消失），窗口仍停在打字状态，键盘上的字母、数字键不会传给游戏；回一下桌面再切回来即可恢复。
- 《阴阳师》走菜单（探索、御魂选层等）约 44 fps，进出战斗读条时会停顿 1 秒上下：这是游戏主逻辑在 arm64 转译下的开销，不是显卡或磁盘。同一台电脑上开着别的模拟器时更明显（实测同机三台模拟器挂机时庭院和战斗约 50 fps）。

## 怎么更新

- 在 AUTO-MAS 里关掉所有实例再更新；关掉后稍等半分钟，模拟器的附属进程退出要十几秒，覆盖时提示文件被占用就再等一会儿重试。这一版包根多了 `ModAVD.exe`（管理器）、`tools\modavd.exe`（命令行）和 `tools\modavd-bridge.ps1`（arm64 执行桥的安装 / 卸载 / 检查），`components` 里多了宿主输入法 `modavd-ime.apk`：手动更新时用新包整个覆盖解压（`avd` 文件夹不会被动到），只换 `sdk\emulator` 就会少了它们。不用重新下载组件，也不用在 AUTO-MAS 里重新添加。
- 执行桥（玩只有 arm64 版本的《阴阳师》要用）不用自己装：升级后用管理器 `ModAVD.exe` 把每台实例开一次机，就会自动装上（第一次要多关机再开机一两次，约 1–2 分钟），之后照常用 AUTO-MAS 开机，桥一直在。只用 AUTO-MAS 开机、从不用管理器的实例，这一版还不会自动装。
- **要退回更早的版本，先在每一台实例上运行一次 `tools\modavd.exe bridge <编号> uninstall`**（在包根打开 PowerShell 运行），看到结果是「没装」再换包；卸过的实例以后开机不会再自动装。这一版起用管理器开过机的实例都装了桥。不先卸就退版，那台实例可能变成「系统属性指着一个已经不存在的库」，所有只有 arm64 版本的应用都跑不起来，而且界面上完全看不出来。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击「补全组件.bat」下载 adb 和系统镜像，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 mas-32 相同。这一版对 AUTO-MAS 没有新要求：arm64 执行桥由包里的管理器 / 命令行装，装过桥的实例照常用 AUTO-MAS 开机。

## 已知问题

- 带窗口时底边上滑无法回桌面或打开最近任务，使用侧边栏的主页键。（[#1](https://github.com/ModAVD/ModAVD/issues/1)）
- 删除游戏或文件后虚拟磁盘不缩小；后续写入会复用空间。（[#2](https://github.com/ModAVD/ModAVD/issues/2)）
- FAT32 / exFAT 上的首次建盘空间检查尚未实测，建议使用 NTFS。（[#3](https://github.com/ModAVD/ModAVD/issues/3)）
- 只支持 x86_64 系统镜像。（[#4](https://github.com/ModAVD/ModAVD/issues/4)）

- 装桥那一轮，名单外的游戏（明日方舟、星铁、终末地）日志里都有撤回那一行，执行桥对它们不生效。
- 关机一律先 sync 再结束模拟器；这一轮不做硬杀测试。数据盘读写的代码和 mas-32 相同，这一版没有重跑强杀测试。
- 执行桥的转发库是 10-29 对照测试（新的信号入口，连续 10 次冷启动 0 ANR）那一份加上按包名分流；伴生库加了 fork 保护（修好约五分之一冷启动卡在「正在获取音频列表...」的问题，修后连续 15 次冷启动 0 次）和分流时的撤回。哈希见包里的 `modavd-manifest.json`。
