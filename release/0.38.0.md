ModAVD 0.38.0，构建号 `mas-38`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见仓库 README 与 `docs/`。

## 更新内容

### 新增

- 可以只让实例里指定的应用走代理，其余照常直连：命令行 modavd proxy，或管理器实例卡片菜单的「按应用走代理…」；暂不支持要账号密码的代理。（[#81](https://github.com/ModAVD/ModAVD/issues/81)）
- 可以整理数据盘：关机后用 modavd disk <编号> compact 或管理器的「整理磁盘」，丢掉安卓里已删除的内容、缩小文件；新盘校验通过才换上，失败保留原盘。（[#2](https://github.com/ModAVD/ModAVD/issues/2)、[#95](https://github.com/ModAVD/ModAVD/issues/95)）

### 变更

- 模拟器重新编译（mas-37 到 mas-38），同步了上游 gfxstream 的一批改动。
- 窗口标题改成实例名；精简窗口自己画标题栏，右边是 ◁ ○ − ×（返回、桌面、最小化、关机），画面右侧那一列去掉了，也不再有最大化。（[#58](https://github.com/ModAVD/ModAVD/issues/58)、[#59](https://github.com/ModAVD/ModAVD/issues/59)）
- write-combined 内存仍默认按 cached 分配，改用上游 gfxstream 的写法，行为不变。（[#37](https://github.com/ModAVD/ModAVD/issues/37)）
- 包里的管理器和命令行升到 0.4.0，详见 [ModAVDManager 的 Release](https://github.com/ModAVD/ModAVDManager/releases)；新建实例默认 1080p；正在新建的实例 stop 默认提示忙（[#103](https://github.com/ModAVD/ModAVD/issues/103)）；exFAT / FAT32 上的根目录不能自动换包，请手动下载整包。

### 修复

- 点 × 改走安卓自己的正常关机（先 sync 再关机），前台应用会先收到关机通知；暂停中的实例先恢复再关。（[#60](https://github.com/ModAVD/ModAVD/issues/60)）
- 图形：游戏进程退出后按进程回收 EGL 资源（[#38](https://github.com/ModAVD/ModAVD/issues/38)）；ASTC / ETC2 压缩纹理能正确解压，没有原生 ASTC 的显卡上不再花屏或全黑（[#39](https://github.com/ModAVD/ModAVD/issues/39)）；游戏进程被杀后渲染线程不再一直等它，不会因此卡死整台模拟器（[#40](https://github.com/ModAVD/ModAVD/issues/40)）。
- FAT32 / exFAT 上首次建数据盘按实际需要的空间检查，不再固定要上限的 1.2 倍。（[#3](https://github.com/ModAVD/ModAVD/issues/3)）
- 游戏里的视频解码更稳。（[#43](https://github.com/ModAVD/ModAVD/issues/43)）
- 整个根目录搬走以后，装过执行桥的实例也能开机了；老实例先在原位置用新版开关机一次再搬。（[#99](https://github.com/ModAVD/ModAVD/issues/99)）

### 说明

- 点 × 以后模拟器进程还会在后台跑一会儿（通常几秒到十几秒，最长约半分钟），请不要结束它。
- FAT32 / exFAT 上首次建盘只在 NTFS 上实测过，有问题请到 [#3](https://github.com/ModAVD/ModAVD/issues/3) 反馈。

## 怎么更新

- 这一版重编了模拟器（mas-37 到 mas-38），管理器和命令行升到 0.4.0；执行桥和宿主输入法和 0.37.1 一样，没有变。
- 先关掉所有实例（在 AUTO-MAS 或管理器里关机）再更新；关掉后稍等半分钟，模拟器的附属进程退出要十几秒，覆盖时提示文件被占用就再等一会儿重试。手动更新时用新包整个覆盖解压，`avd` 文件夹不会被动到。不用重新下载组件，也不用在 AUTO-MAS 里重新添加。
- 管理器 0.4.0 的自动换包（`modavd update`）要求根目录所在的盘支持按文件 ID 打开程序文件（NTFS 可以）；放在 exFAT / FAT32 上的根目录会拒绝自动换包、什么都不动，请手动下载整包覆盖。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击「补全组件.bat」下载 adb 和系统镜像，再双击 `ModAVD.exe` 新建实例；要接入 AUTO-MAS 的，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 0.37.1 相同。这一版对 AUTO-MAS 没有新要求。

## 已知问题

- 删除游戏或文件后虚拟磁盘不会自动缩小，模拟器的 trim 还不会真正回收空间；要省空间，请在关机后用管理器的「整理磁盘」或命令行 `modavd disk <编号> compact`。（[#2](https://github.com/ModAVD/ModAVD/issues/2)）
- 《阴阳师》冷启动偶尔停在「正在获取音频列表...」，关掉重开即可。（[#36](https://github.com/ModAVD/ModAVD/issues/36)）
- AUTO-MAS 自己起的模拟器（不经过管理器或命令行），多开时 netsimd 还可能卡住，之后所有实例都开不了机；在任务管理器里结束 netsimd 进程再开机就好。用管理器或命令行开机的实例已经不用 netsimd 了。（[#65](https://github.com/ModAVD/ModAVD/issues/65)）
- Windows 注销、重启或关机时，开着的实例还是直接断电，不会先让安卓关机，和以前一样。关电脑前请先在 AUTO-MAS 或管理器里关掉实例。（[#60](https://github.com/ModAVD/ModAVD/issues/60)）
- 《明日方舟》偶尔在启动时报资源管理器初始化失败，随后把约 12.8 GB 的资源整包重新下载一遍；遇到过一次，排查没有发现模拟器丢数据，更像游戏自己把资源索引作废了，等它下完即可。（[#89](https://github.com/ModAVD/ModAVD/issues/89)）

## English

ModAVD 0.38.0, build `mas-38`, built on Google AOSP Android Emulator 37.2.10. Installation, upgrades and feedback: see https://modavd.github.io/.

### New

- You can send only the apps you choose in an instance through a proxy while the rest connect directly: `modavd proxy` on the command line, or "Per-app proxy…" in the instance card menu of the manager. Proxies that need a username and password are not supported yet. ([#81](https://github.com/ModAVD/ModAVD/issues/81))
- You can compact the data disk: after shutdown, use `modavd disk <number> compact` or "compact disk" in the manager to drop what Android has deleted and shrink the file. The new disk replaces the old one only after it passes verification; on any failure the original is kept. ([#2](https://github.com/ModAVD/ModAVD/issues/2), [#95](https://github.com/ModAVD/ModAVD/issues/95))

### Changes

- The emulator is rebuilt (mas-37 to mas-38) with a batch of upstream gfxstream changes.
- The window title is now the instance's name. The lean window draws its own title bar with ◁ ○ − × (back, home, minimize, shut down) on the right; the column on the right of the screen is gone, and there is no maximize any more. ([#58](https://github.com/ModAVD/ModAVD/issues/58), [#59](https://github.com/ModAVD/ModAVD/issues/59))
- Write-combined memory is still allocated as cached by default, now the way upstream gfxstream does it; behavior is unchanged. ([#37](https://github.com/ModAVD/ModAVD/issues/37))
- The manager and the command line in the package go to 0.4.0 (see the [ModAVDManager releases](https://github.com/ModAVD/ModAVDManager/releases)); new instances default to 1080p; `stop` on an instance that is still being created reports busy by default ([#103](https://github.com/ModAVD/ModAVD/issues/103)); a root folder on exFAT / FAT32 cannot swap the package automatically, so download the whole package by hand.

### Fixes

- Clicking × now goes through Android's own shutdown (sync first, then power off), so the foreground app is told before it ends; a paused instance is resumed first. ([#60](https://github.com/ModAVD/ModAVD/issues/60))
- Graphics: EGL resources are released per process when a game exits ([#38](https://github.com/ModAVD/ModAVD/issues/38)); ASTC / ETC2 compressed textures are decompressed correctly, so they no longer come out garbled or black on GPUs without native ASTC ([#39](https://github.com/ModAVD/ModAVD/issues/39)); after a game process is killed, the render thread no longer waits for it forever and cannot freeze the whole emulator that way ([#40](https://github.com/ModAVD/ModAVD/issues/40)).
- On FAT32 / exFAT, the free-space check for creating the first data disk uses the space actually needed instead of always 1.2 times the limit. ([#3](https://github.com/ModAVD/ModAVD/issues/3))
- Video decoding in games is steadier. ([#43](https://github.com/ModAVD/ModAVD/issues/43))
- After the whole root folder is moved, instances that have the execution bridge can boot again; start and shut down an old instance once with the new version in its original place before moving. ([#99](https://github.com/ModAVD/ModAVD/issues/99))

### Notes

- After you click ×, the emulator process keeps running in the background for a while (usually from a few seconds to a dozen or so, at most about half a minute). Please do not end it.
- Creating the first disk on FAT32 / exFAT has been tested on NTFS only; if you run into a problem, please tell us in [#3](https://github.com/ModAVD/ModAVD/issues/3).

### How to update

- This version rebuilds the emulator (mas-37 to mas-38) and moves the manager and the command line to 0.4.0; the execution bridge and the host input method are the same as in 0.37.1.
- Shut down all instances first (in AUTO-MAS or in the manager), then wait about half a minute: the emulator's helper processes take a dozen seconds or so to exit. If extracting reports a file in use, wait a little and try again. To update by hand, extract the whole new package over the old one; the `avd` folder is left alone. There is no need to download the components again or to add ModAVD to AUTO-MAS again.
- The automatic package swap of manager 0.4.0 (`modavd update`) needs the drive holding the root folder to support opening program files by file ID (NTFS does). A root folder on exFAT / FAT32 is refused with nothing changed; please download the whole package and extract it over the old one by hand.
- First install: the main package has no top-level folder, so use "Extract All…" or 7-Zip "Extract to <package name>\". Then double-click 补全组件.bat to download adb and the system image, and double-click `ModAVD.exe` to create an instance. To use it with AUTO-MAS, add it there as well; see 说明.txt.

### AUTO-MAS version

- `v5.7.0` or later is recommended, as for 0.37.1. This version has no new requirements for AUTO-MAS.

### Known issues

- The virtual disk does not shrink by itself after games or files are deleted, and the emulator's trim does not actually reclaim space yet; to save space, after shutdown use "compact disk" in the manager or `modavd disk <number> compact`. ([#2](https://github.com/ModAVD/ModAVD/issues/2))
- Onmyoji occasionally stops at "正在获取音频列表..." (fetching the audio list) during a cold start; close it and start it again. ([#36](https://github.com/ModAVD/ModAVD/issues/36))
- Emulators that AUTO-MAS starts itself (not through the manager or the command line) can still hit a hung netsimd with several instances, after which no instance can start; end the netsimd process in Task Manager and start again. Instances started from the manager or the command line no longer use netsimd. ([#65](https://github.com/ModAVD/ModAVD/issues/65))
- When Windows logs off, restarts or shuts down, running instances are still cut off without letting Android shut down first, as before. Shut the instances down in AUTO-MAS or the manager before turning off the computer. ([#60](https://github.com/ModAVD/ModAVD/issues/60))
- Arknights occasionally reports a resource manager initialization failure at startup and then downloads the whole ~12.8 GB of resources again. It has been seen once; the investigation found no sign of the emulator losing data, and it looks more like the game invalidating its own resource index. Let the download finish. ([#89](https://github.com/ModAVD/ModAVD/issues/89))
