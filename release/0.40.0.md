ModAVD 0.40.0，构建号 `mas-40`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见[文档站](https://modavd.github.io/)。

## 更新内容

### 新增

- 老板键：每台带窗口的实例一个全局快捷键（编号 0–9 默认 Ctrl+Alt+Shift+编号），按一下藏起窗口、再按叫回；关掉管理器窗口后管理器留在托盘。（[#101](https://github.com/ModAVD/ModAVD/issues/101)）
- 实例帧率可以在 1–60 之间任选，不再只有 30 / 60。（[#180](https://github.com/ModAVD/ModAVD/issues/180)）
- 数据盘默认自动扩盘：一开始就是 256 GB，电脑上只按实际写入占空间；已有实例下次开机自动扩到 256 GB，数据不动。也可以改成指定大小。（[#153](https://github.com/ModAVD/ModAVD/issues/153)）

### 变更

- 明日方舟的下载目录放到单独的下载盘上，下资源从约 11 MiB/s 提到约 90 MiB/s；模拟器被强行结束时下载目录整个回到几秒前，游戏接着下。（[#35](https://github.com/ModAVD/ModAVD/issues/35)）
- modavd update 从 GitHub 更新时只下变了的文件，不用 Mirror 酱 CDK。（[#171](https://github.com/ModAVD/ModAVD/issues/171)）
- 带窗口的实例放开系统的最大化和贴边吸附，比例对不上时画面居中留黑边。（[#161](https://github.com/ModAVD/ModAVD/issues/161)）
- 模拟器重新编译（mas-39 到 mas-40）；包里的管理器和命令行升到 0.8.0，截图库升到 v0.1.2。

### 修复

- Windows 注销、重启或关机时，没有窗口的实例也先 sync、再让安卓关机，不再直接断电。（[#64](https://github.com/ModAVD/ModAVD/issues/64)）
- 带窗口的实例被别的窗口挡住时，点标题栏就能把它激活、提到最前。（[#160](https://github.com/ModAVD/ModAVD/issues/160)）

## 怎么更新

- 模拟器重新编译（mas-40）；包里的管理器和命令行升到 0.8.0（改动见 [它的 Release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.8.0)），截图库升到 [v0.1.2](https://github.com/ModAVD/ModAVDExtras/releases/tag/v0.1.2)；执行桥、宿主输入法和 0.39.1 一样。
- 更新以后，已有实例下次开机前数据盘会自动扩到 256 GB（开机时在线扩，游戏数据不动，电脑上多占不到 1 GB，之后按实际写入增长）。不想要的，在管理器的实例设置里改成「指定大小」，或运行 `tools\modavd.exe set <编号> --data-gb <大小>`。（[#153](https://github.com/ModAVD/ModAVD/issues/153)）
- 从 0.39.1 起可以在管理器「设置」里点「更新」；也可以先关掉所有实例（在 AUTO-MAS 或管理器里关机），稍等半分钟，再用新包整个覆盖解压，`avd` 文件夹不会被动到。不用在 AUTO-MAS 里重新添加。
- 关掉管理器窗口以后管理器留在托盘里；手动覆盖更新前，请在托盘图标的右键菜单里点「退出」。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击 `ModAVD.exe`，点上方提示里的「补全组件」下载 adb 和系统镜像，再新建实例；要接入 AUTO-MAS 的，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 0.39.1 相同。这一版对 AUTO-MAS 没有新要求：管理器 0.8.0 的接口版本（`protocol`）还是 2，只加了参数和字段。新建实例不给数据盘大小时是 256 GB（自动扩盘），还在 AUTO-MAS 允许的 16–512 GB 里。
- AUTO-MAS 5.8.0 在组件不全时还会提示双击「补全组件.bat」，0.38.2 起包里没有这个文件：请在管理器里点「补全组件」，或运行 `tools\modavd.exe components fetch`，再回 AUTO-MAS 点「检查」。
- `modavd update` 只下变了的文件（[#171](https://github.com/ModAVD/ModAVD/issues/171)）要等 AUTO-MAS 改成调 `modavd update` 的版本发布后才用得上；现在的 AUTO-MAS 照旧用它自己的更新器。

## 已知问题

- 删除游戏或文件后虚拟磁盘不会自动缩小，模拟器的 trim 还不会真正回收空间；要省空间，请在关机后用管理器的「整理磁盘」或命令行 `modavd disk <编号> compact`。（[#2](https://github.com/ModAVD/ModAVD/issues/2)）
- 《阴阳师》冷启动偶尔停在「正在获取音频列表...」，关掉重开即可。（[#36](https://github.com/ModAVD/ModAVD/issues/36)）
- AUTO-MAS 自己起的模拟器（不经过管理器或命令行），多开时 netsimd 还可能卡住，之后所有实例都开不了机；在任务管理器里结束 netsimd 进程再开机就好。用管理器或命令行开机的实例已经不用 netsimd 了。（[#65](https://github.com/ModAVD/ModAVD/issues/65)）
- 《明日方舟》偶尔在启动时报资源管理器初始化失败，随后把约 12.8 GB 的资源整包重新下载一遍；遇到过两次，排查都没有发现模拟器丢数据，更像游戏自己把资源索引作废了，等它下完即可。（[#89](https://github.com/ModAVD/ModAVD/issues/89)）

## English

ModAVD 0.40.0, build `mas-40`, built on Google AOSP Android Emulator 37.2.10. Installation, upgrades and feedback: see https://modavd.github.io/.

### New

- Boss key: one global hotkey per windowed instance (instances 0–9 default to Ctrl+Alt+Shift+number); press it to hide the window and again to bring it back. Closing the manager window now leaves the manager in the tray. ([#101](https://github.com/ModAVD/ModAVD/issues/101))
- The instance frame rate can be anything from 1 to 60, no longer only 30 or 60. ([#180](https://github.com/ModAVD/ModAVD/issues/180))
- The data disk grows automatically by default: it is 256 GB from the start and takes space on the computer only for what is actually written; existing instances grow to 256 GB at their next boot, with their data untouched. A fixed size can be chosen instead. ([#153](https://github.com/ModAVD/ModAVD/issues/153))

### Changes

- Arknights' download folder is put on a separate download disk, so resource downloads go from about 11 MiB/s to about 90 MiB/s; if the emulator is killed, the whole download folder goes back to a few seconds earlier and the game carries on downloading. ([#35](https://github.com/ModAVD/ModAVD/issues/35))
- `modavd update` downloads only the changed files when updating from GitHub, without a Mirror 酱 CDK. ([#171](https://github.com/ModAVD/ModAVD/issues/171))
- Windowed instances can be maximized and snapped by the system; when the aspect ratio does not match, the picture is centred with black bars. ([#161](https://github.com/ModAVD/ModAVD/issues/161))
- The emulator is rebuilt (mas-39 to mas-40); the manager and the command line in the package go to 0.8.0, and the capture library to v0.1.2.

### Fixes

- When Windows logs off, restarts or shuts down, instances without a window also sync and let Android shut down first instead of being cut off. ([#64](https://github.com/ModAVD/ModAVD/issues/64))
- Clicking the title bar of a windowed instance that is covered by another window now activates it and brings it to the front. ([#160](https://github.com/ModAVD/ModAVD/issues/160))

### How to update

- The emulator is rebuilt (mas-40); the manager and the command line in the package go to 0.8.0 (see [its release](https://github.com/ModAVD/ModAVDManager/releases/tag/v0.8.0)), and the capture library to [v0.1.2](https://github.com/ModAVD/ModAVDExtras/releases/tag/v0.1.2); the execution bridge and the host input method are the same as in 0.39.1.
- After the update, existing instances grow their data disk to 256 GB before their next boot (it is enlarged online at boot, game data is untouched, it takes less than 1 GB more on the computer and then grows with what is actually written). If you do not want that, switch the instance to "指定大小" (fixed size) in its settings in the manager, or run `tools\modavd.exe set <number> --data-gb <size>`. ([#153](https://github.com/ModAVD/ModAVD/issues/153))
- From 0.39.1 on you can click "更新" (update) in the manager's "设置" (settings); or shut down all instances first (in AUTO-MAS or in the manager), wait about half a minute, and extract the whole new package over the old one; the `avd` folder is left alone. There is no need to add ModAVD to AUTO-MAS again.
- Closing the manager window leaves the manager in the tray; before updating by hand, click "退出" (exit) in the tray icon's right-click menu.
- First install: the main package has no top-level folder, so use "Extract All…" or 7-Zip "Extract to <package name>\". Then double-click `ModAVD.exe`, click "补全组件" in the notice at the top to download adb and the system image, and create an instance. To use it with AUTO-MAS, add it there as well; see `说明.txt`.

### AUTO-MAS version

- `v5.7.0` or later is recommended, as for 0.39.1. This version has no new requirements for AUTO-MAS: the interface version (`protocol`) of manager 0.8.0 is still 2, with only new options and fields. A new instance created without a data disk size gets 256 GB (automatic growth), which is within the 16–512 GB AUTO-MAS allows.
- When components are missing, AUTO-MAS 5.8.0 still says to double-click `补全组件.bat`, which is not in the package from 0.38.2 on: click "补全组件" in the manager or run `tools\modavd.exe components fetch`, then go back to AUTO-MAS and click "检查" (check).
- Downloading only the changed files with `modavd update` ([#171](https://github.com/ModAVD/ModAVD/issues/171)) helps AUTO-MAS users only once an AUTO-MAS release calls `modavd update`; the current AUTO-MAS still uses its own updater.

### Known issues

- The virtual disk does not shrink by itself after games or files are deleted, and the emulator's trim does not actually reclaim space yet; to save space, after shutdown use "compact disk" in the manager or `modavd disk <number> compact`. ([#2](https://github.com/ModAVD/ModAVD/issues/2))
- Onmyoji occasionally stops at "正在获取音频列表..." (fetching the audio list) during a cold start; close it and start it again. ([#36](https://github.com/ModAVD/ModAVD/issues/36))
- Emulators that AUTO-MAS starts itself (not through the manager or the command line) can still hit a hung netsimd with several instances, after which no instance can start; end the netsimd process in Task Manager and start again. Instances started from the manager or the command line no longer use netsimd. ([#65](https://github.com/ModAVD/ModAVD/issues/65))
- Arknights occasionally reports a resource manager initialization failure at startup and then downloads the whole ~12.8 GB of resources again. It has been seen twice; neither investigation found the emulator losing data, and it looks more like the game invalidating its own resource index. Let the download finish. ([#89](https://github.com/ModAVD/ModAVD/issues/89))

### Pre-release regression

The regression used this version's candidate package: the emulator is the mas-40 that ships; the manager and the command line are 0.8.0 from the head of ModAVDManager's `release/0.40` (not tagged yet; the tag goes on that commit at release, and two builds are byte for byte the same); the capture library is the v0.1.2 release asset; the host input method and the execution bridge are the same as in 0.39.1. Upgrading from 0.39.1 (by `modavd update` downloading only the changed files — 113 MB of the 301 MB package, from a local stand-in for GitHub because this version is not published yet — by 0.39.1's own `update install`, and by extracting over it), booting and shutting down headless and windowed instances, the picture and touch input of a windowed instance, closing a windowed instance with × (sync first, then Android's own shutdown), a headless instance receiving Windows' end-of-session messages (sent by hand, not a real log-off), the boss key and the tray, a 45 fps frame rate, the Arknights download disk (a fresh install downloaded the full 15.3 GB of resources at about 91 MiB/s), automatic and fixed-size data disks (old 96 / 64 / 16 GB disks grew to 256 GB with data intact; a new 256 GB disk takes about as much space on the computer as a new 32 GB one), World of Airports, Arknights, Reverse: 1999, Honkai: Star Rail and Honkai Impact 3rd, the capture library with MaaCore, creating instances with the execution bridge and with a new data disk, the host input method, fetching components, the package contents and the privacy scan all passed. Maximizing, snapping, black bars and real mouse dragging of windowed instances ([#161](https://github.com/ModAVD/ModAVD/issues/161)) and activating by a title bar click ([#160](https://github.com/ModAVD/ModAVD/issues/160)) are tested separately by the maintainer on real hardware. Not tested: a real Windows log-off, restart or shutdown; automatic disk growth on an instance started by AUTO-MAS; downloading this version for real from GitHub or Mirror 酱 (after the release); the manager window itself (only the tray was used). The results table is in the Chinese section above.
