ModAVD 0.38.1，构建号 `mas-38`，基于 Google AOSP Android Emulator 37.2.10 构建。安装、升级和反馈见仓库 README 与 `docs/`。

## 更新内容

### 变更

- 包里的管理器和命令行升到 0.4.1，模拟器还是 mas-38，没有重编。

### 修复

- 0.37.0 到 0.38.0 的「补全组件.bat」装系统镜像必然失败，已修；用旧包的也可以在根目录运行 tools\modavd.exe components fetch。（[#118](https://github.com/ModAVD/ModAVD/issues/118)）
- 关机后马上自动换包，偶尔把正在退出的辅助进程当成占用而拒绝，已修；从 0.38.1 往后的更新生效。（[#77](https://github.com/ModAVD/ModAVD/issues/77)）

## 怎么更新

- 这一版只重新打包：模拟器还是 mas-38，没有重编；包里的管理器和命令行升到 0.4.1；执行桥、宿主输入法都和 0.38.0 一样。
- 主要修的是「补全组件.bat」：0.37.0 到 0.38.0 的包第一次装系统镜像必然失败，报「解压后的关键文件或版本校验失败」。已经装好、能开机的不受影响，不用重新下载组件。
  - 用旧包装不上的，下载这一版的包，解压后双击「补全组件.bat」。已经下好的系统镜像压缩包放在 `downloads\` 里，会直接用，不用重下。
  - 或者不换包：在旧包的根目录打开命令行，运行 `tools\modavd.exe components fetch`，看完许可协议输入 `y`。
- 先关掉所有实例（在 AUTO-MAS 或管理器里关机）再更新；关掉后稍等半分钟再覆盖。手动更新时用新包整个覆盖解压，`avd` 文件夹不会被动到。不用在 AUTO-MAS 里重新添加。
- 自动换包（`modavd update`）这次还是由 0.38.0 里的旧命令行来做：关机后马上更新，偶尔会提示有程序在用，什么都没动，过半分钟再更新一次就好。从 0.38.1 往后的更新不再有这个问题。
- 第一次装：主包里没有外层文件夹，请用右键「全部解压缩」或 7-Zip「解压到 <包名>\」。解压后双击「补全组件.bat」下载 adb 和系统镜像，再双击 `ModAVD.exe` 新建实例；要接入 AUTO-MAS 的，再到 AUTO-MAS 里添加，详见 `说明.txt`。

## AUTO-MAS 版本

- 推荐 `v5.7.0` 或更新，和 0.38.0 相同。这一版对 AUTO-MAS 没有新要求。

## English

ModAVD 0.38.1, build `mas-38`, built on Google AOSP Android Emulator 37.2.10. Installation, upgrades and feedback: see https://modavd.github.io/.

### Changes

- The manager and the command line in the package go from 0.4.0 to 0.4.1; the emulator is still mas-38 and was not rebuilt. See the [ModAVDManager releases](https://github.com/ModAVD/ModAVDManager/releases) for what changed in them.

### Fixes

- In 0.37.0 to 0.38.0, `补全组件.bat` (fetches the Google components) always failed on its first install of the system image, with "解压后的关键文件或版本校验失败" (the key files or version check failed after extraction). It now installs it, and the reason for a failed check is written to `logs\fetch-components.log`. With an older package, you can also run `tools\modavd.exe components fetch` in the root folder instead. ([#118](https://github.com/ModAVD/ModAVD/issues/118))
- Swapping the package automatically (`modavd update`) right after a shutdown could now and then be refused, because a helper process that was just exiting was taken for one still in use; a `status` call AUTO-MAS makes on a timer no longer makes it refuse either. The swap is done by the command line already installed, so this applies to updates from 0.38.1 on. ([#77](https://github.com/ModAVD/ModAVD/issues/77))

### How to update

- This version only repackages: the emulator is still mas-38, the manager and the command line go to 0.4.1, and the execution bridge and the host input method are the same as in 0.38.0.
- The main fix is `补全组件.bat`. If your root folder already has its components and boots, nothing changes for you, and there is no need to download the components again.
  - If the first install failed with an older package, download this package and double-click `补全组件.bat` after extracting it. A system image zip already in `downloads\` is used as it is, without downloading it again.
  - Or keep the old package: open a command prompt in its root folder, run `tools\modavd.exe components fetch`, and type `y` after reading the license agreement.
- Shut down all instances first (in AUTO-MAS or in the manager), then wait about half a minute before extracting. To update by hand, extract the whole new package over the old one; the `avd` folder is left alone. There is no need to add ModAVD to AUTO-MAS again.
- This time the automatic swap (`modavd update`) is still done by the command line of 0.38.0: right after a shutdown it may now and then say a program is in use and change nothing; wait half a minute and update again. Updates from 0.38.1 on no longer do this.
- First install: the main package has no top-level folder, so use "Extract All…" or 7-Zip "Extract to <package name>\". Then double-click `补全组件.bat` to download adb and the system image, and double-click `ModAVD.exe` to create an instance. To use it with AUTO-MAS, add it there as well; see `说明.txt`.

### AUTO-MAS version

- `v5.7.0` or later is recommended, as for 0.38.0. This version has no new requirements for AUTO-MAS.

### Known issues

- The virtual disk does not shrink by itself after games or files are deleted, and the emulator's trim does not actually reclaim space yet; to save space, after shutdown use "compact disk" in the manager or `modavd disk <number> compact`. ([#2](https://github.com/ModAVD/ModAVD/issues/2))
- Onmyoji occasionally stops at "正在获取音频列表..." (fetching the audio list) during a cold start; close it and start it again. ([#36](https://github.com/ModAVD/ModAVD/issues/36))
- Emulators that AUTO-MAS starts itself (not through the manager or the command line) can still hit a hung netsimd with several instances, after which no instance can start; end the netsimd process in Task Manager and start again. Instances started from the manager or the command line no longer use netsimd. ([#65](https://github.com/ModAVD/ModAVD/issues/65))
- When Windows logs off, restarts or shuts down, running instances are still cut off without letting Android shut down first, as before. Shut the instances down in AUTO-MAS or the manager before turning off the computer. ([#60](https://github.com/ModAVD/ModAVD/issues/60))
- Arknights occasionally reports a resource manager initialization failure at startup and then downloads the whole ~12.8 GB of resources again. It has been seen once; the investigation found no sign of the emulator losing data, and it looks more like the game invalidating its own resource index. Let the download finish. ([#89](https://github.com/ModAVD/ModAVD/issues/89))
